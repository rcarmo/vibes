# Plan: Add Pi Mode to Vibes

## Goals
- Add a **Pi mode** agent integration alongside existing ACP.
- Preserve ACP functionality (separate code paths, no breaking changes).
- Map Pi RPC events to Vibes UI features: **history**, **draft/thinking streams**, **tool activation**, and **media handling**.
- Make Pi selectable via configuration (default agent stays ACP unless configured).

## High-level Architecture
1. **Pi RPC Client** (`src/vibes/pi_client.py`)
   - Spawn `pi --mode rpc` as a subprocess.
   - Send prompts and read JSON line events.
   - Map Pi streaming events to Vibes SSE callbacks:
     - `message_update` → `agent_draft` (text delta) and `agent_thought` (thinking delta)
     - `tool_execution_*` → `agent_status` (tool call/status)
   - Support Pi extension UI requests (`extension_ui_request`) via Vibes’ existing `agent_request` modal.
   - Return `{text, content}` payloads aligned with ACP responses for storage.

2. **Agent Routing** (`src/vibes/routes/agents.py`)
   - Route requests by agent id and a new config default.
   - Keep ACP as-is; Pi is an additional path.
   - Ensure `POST /agent/respond` can respond to both ACP and Pi extension UI requests.

3. **Media Handling**
   - Convert Pi content blocks and attachments to Vibes content blocks.
   - Reuse `_store_media_block` to persist images/files into the media table.
   - Store `content_blocks` + `media_ids` in interactions, just like ACP.

4. **Configuration** (`src/vibes/config.py`, `docs/CONFIGURATION.md`)
   - New env vars:
     - `VIBES_DEFAULT_AGENT` (default: `acp`)
     - `VIBES_PI_AGENT` (default: `pi --mode rpc --no-session`)
     - `VIBES_PI_ENABLED` (default: `false`, auto-true when default agent is `pi`)

5. **Lifecycle & SSE Restart** (`src/vibes/app.py`, `src/vibes/routes/sse.py`)
   - Start/stop Pi agent only when enabled.
   - Keep ACP start/stop unchanged.
   - Restart Pi agent on SSE disconnect if configured (mirrors ACP behavior).

## Implementation Steps
1. **Create `pi_client.py`**
   - Implement subprocess management, request lock, event loop, and response parsing.
   - Map Pi events to Vibes status callbacks.
   - Translate Pi messages → Vibes content blocks.
   - Implement extension UI request handling + response routing.

2. **Update Config + Startup**
   - Add Pi config options.
   - Start Pi agent if enabled.

3. **Route to Pi in `routes/agents.py`**
   - Resolve agent mode (`acp` vs `pi`) by id or default.
   - Use Pi client for message handling when selected.

4. **Wire extension UI responses**
   - `POST /agent/respond` should handle both ACP and Pi pending requests.

5. **Update SSE restart logic**
   - Restart Pi agent on disconnect when enabled.

6. **Document Pi mode usage**
   - Update configuration docs to show enabling Pi.

## Non-goals / Known Limits (initial cut)
- Custom Pi extension UI dialogs beyond `confirm/select` will be auto-cancelled (until Vibes has richer input widgets).
- Pi tool rendering is summarized via status updates, not full tool output UI.

## Success Criteria
- Switching `VIBES_DEFAULT_AGENT=pi` uses Pi mode with streaming drafts/thoughts and tool activation status.
- Media generated by Pi (images/files/attachments) appears in the Vibes timeline.
- ACP continues to work unchanged.
